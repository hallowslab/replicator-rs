Replication worker release.

`replicator-rs` reads the durable record store written by `rftps` and `recv`
(`--record-store`) and replays uploads to remote storage. It is the only piece
that talks to the broker or to storage; the upload servers never do.

### Highlights

- **Durable queue** - SQLite (WAL) store with `pending` / `in-flight` / `done`
  transitions, crash-safe resume, retry backoff, and a 72h dead-letter cap.
- **Broker mode** - zero-trust device registration and approval against the
  ExifFlow Access Broker; storage credentials are fetched at runtime and held in
  memory only.
- **Static storage mode** - skip the broker and point at an S3 or FTPS target
  directly in `bg.json`.
- **Resumable multipart S3** - uploads persist `upload_id` and completed parts,
  so a failed upload resumes instead of restarting from zero.
- **Pluggable features** - `broker` (Ed25519 device keys + broker client) and
  `s3` (S3 backend) are default-on.

### Binaries

- `replicator-rs-full` - default features (`broker` + `s3`).
- `replicator-rs-ftps` - built with `--no-default-features` (static FTPS target
  only, no broker/S3).

### CLI

- `replicator-rs init` - interactive `bg.json` generator (broker device key + URL).
- `replicator-rs keygen` - print a raw Ed25519 device key.
- `--store <path>` - durable store written by `rftps`/`recv` `--record-store`.
- `--config <path>` - `bg.json` replication config.
- `--multipart-threshold <bytes>`, `--max-part-size <bytes>` - override the baked
  S3 multipart defaults.
